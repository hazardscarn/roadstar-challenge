# Alfred — AI Fleet Dispatch

An AI (Google OR-Tools CP-SAT) day-ahead dispatch system for a Southern Ontario trucking fleet:
a manager plans and finalizes tomorrow's truck/driver/order assignments, a fast simulation replays
that plan on a live map, and drivers get a mobile-first "Driver Assist" view of their own real
assigned trips for the day.

Backed throughout by real historical data (`ground_truth.*` — real drivers, trucks, orders, legs)
where it exists, with every synthesized figure (fuel price, dwell time, HOS starting point, etc.)
labeled as such rather than presented as fact. See `documents/results/` and
`documents/deck/ai_dispatch_optimization/README.md` for the validated backtest (46 real days,
REAL dispatcher vs. the AI solver) and its methodology.

## Quick start

**Backend** (Python 3.12, FastAPI + a direct Postgres/Supabase connection):

```bash
python -m venv venv && source venv/bin/activate
pip install -r requirements.txt
# .env at repo root needs: VITE_SUPABASE_URL, VITE_SUPABASE_ANON_KEY, SUPABASE_DB_URL,
# SUPABASE_SERVICE_ROLE_KEY (ask the team for real values -- not committed, see .gitignore)
uvicorn dashboard.server.main:app --port 8787
```

**Frontend** (React + Vite, reads the same repo-root `.env` via `dashboard/vite.config.ts`'s `envDir`):

```bash
cd dashboard
npm install
npm run dev   # http://localhost:5173, proxies /api to the backend above
```

**Tests**: `pytest sim/tests/` (Python) · `npx tsc --noEmit -p tsconfig.app.json` from `dashboard/` (types) · `npm run build` (frontend build).

                              HOS, chain timing) vs. soft costs (deadhead, lateness) -- see its own
                              module docstring and documents/deck/ai_dispatch_optimization/.
  live/
    dispatch_board.py        Backend for the manager's Dispatch Board: load/save a day's
                              trucks/orders/drivers/assignments, finalize/reopen a day.
    generate_dispatch_day.py Idempotently generates a day's real-data-grounded order book +
                              truck/driver roster the first time that date's board is opened.
    ai_dispatch_replay.py    Takes a FINALIZED day's real assignments and replays them as a fast,
                              full-day multi-truck simulation (trajectories, HOS, detention,
                              invoices) -- what "Live Ops Simulation" plays back. This is the
                              single source of truth for the `simulation.*` schema.
    score_quote.py           Older single-quote candidate-scoring model (pre-dispatch-board

## Real vs. synthesized, at a glance

This project is deliberately explicit about what's real and what's assumed — see `sim/config.py`'s
own comments for the full list, and `documents/deck/ai_dispatch_optimization/README.md` section 3
for the constraints table. The short version: order volumes, lanes, weights, HOS regulation, dwell
times, and the 46-day backtest are all real or real-data-calibrated. Truck/driver home-hub
assignment, the assumed 03:00 earliest-departure time, and a few maintenance/inspection figures are
labeled synthetic assumptions, not backtested facts.
